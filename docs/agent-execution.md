# Agent 执行过程

“诊断与日志”页面已移除，开发者工具提供“Agent 执行”。系统设置 → 高级定制 → 显示开发者工具后可见。它回答一次接待用了哪个助手、经历哪些模型回合、调用什么工具、参数和结果是什么，以及回复最后是否送达。

## 页面

- 「执行记录所属店铺」默认跟随当前店铺，也可选全部店铺；按自动回复/自动学习与执行状态筛选，支持加载更早记录。选全部店铺时列表标明所属店铺。
- 左侧展示助手、买家问题、时间、生成/评估状态和发送状态；右侧按开始顺序展示调用树。展开某个节点查看实际输入、输出、耗时与错误，可复制内容。
- 主 Agent / 子 Agent → 模型回合 → 工具 / Skill / Workflow；Workflow 再展示内部步骤。父节点参数折叠后，子步骤仍可直接查看。
- 运行时刷新，切换页面、重启后仍读取本地持久化记录。模型回合的耗时包含该轮工具执行；并行步骤分别计时。
- 最终正文、图片及发送回执单独展示。“AI 已生成”不会代替“发送成功”；待确认、拒绝、取消保持实际状态，不自动重发。
- 学习展示来源和评估，候选仍需到“自动学习”页面人工审批后生效。
- 历史记录没有逐步数据时明确显示未采集，不从最终回复推测工具轨迹。直答只记录实际问答匹配；未配置可选 Embedding 时，向量匹配标注跳过，继续原有 Agent 路径；前置检查失败明确标注未调用模型。

原后台任务和发送异常表格不再展示；后台调度、回执对账 API 与历史数据保留。系统设置 → 数据与备份的诊断导出保留。Agent Studio 的隔离试运行继续使用原沙箱，不写生产运行记录。

## 持久化

`AiRun.traceVersion = 1` 表示当前采集格式，旧记录默认 0。`AiRunStep` 包含 runId、sequence、parentId、kind、name、toolName、status、input、output、metadata、error、startedAt / finishedAt。

同一运行的序号唯一，真实 toolCallId 加模型轮次关联工具调用，不能只按工具名合并。同名工具并发、重复调用及子 Agent 独立运行不会串结果。开始先保存 running；结果、错误或取消分别落库。应用重启将未完成步骤标记为中断，不继续显示永久运行，也不恢复旧回复发送。

步骤状态包括 running / succeeded / failed / cancelled / unknown / skipped。工具返回错误对象、脚本非零退出/超时/输出超限、业务写入 unknown 不能当作成功。日志采集失败不会重试业务调用。

## 采集位置

- Engine：本店问答检索实际结果、生产 RunTrace、内置学习运行、重启收尾。
- Mastra 原有 prepareStep / onChunk / onStepFinish：每轮输入、公开输出、工具调用和用量。记录 SDK 实际事件，不追加复核或格式整理模型请求。
- 工具执行：开始与结果以真实调用 ID 关联；工具执行期间传递父节点上下文，子 Agent 和 Workflow 归到调用它们的工具下面。
- 原生 Skill 工具通过 Mastra 事件采集；runSkillScript 保存实际脚本、参数、stdout、stderr、退出码与状态。
- Workflow：同一次 run.stream 的步骤开始/结果事件与最终状态，不额外运行工作流。逐步保留真实输入输出。

每步输入输出做有界序列化：长文本/集合明确标注截断，二进制和内嵌图片不展开；密钥字段及宿主解密的扩展/模型密钥被隐藏。模型私有推理不采集，模型后续输入里的 reasoning 内容也过滤。返回业务数据仅进入本机记录，不交给另一个模型分析。

## API

- `runs.history({storeId?, role?, status?, cursor?, limit?})`：默认每页 30 条、最多 100 条，不加载每个步骤的大输入输出。省略 storeId 时返回全部店铺。返回摘要（含店铺名）和 nextCursor；时间相同用 ID 排序。
- `runs.detail({storeId, id})`：校验运行属于该店铺，返回完整步骤及关联发送状态。不能用其他店铺的运行 ID 读取详情。
- 两者都是只读，不触发业务变更事件，避免查询自身引起无限刷新。
- 旧 `runs.list` 为已有调用保留，新的页面不再加载旧后台任务/发送异常集合。

数据迁移随应用启动执行，无需清空已有资料库。未重打安装包时，需要重新构建安装包才能分发此功能。
