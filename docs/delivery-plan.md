# 实施与验收计划

> Workflow 扩展已移除，本文中与 Workflow 相关的内容仅为历史记录，见[本地扩展开发](extension-development.md#workflow-已移除)。

版本：v0.7  
方案日期：2026-09-07  
状态：已提供拼多多、抖店、闲鱼与快手首版实现；实际交付、验证证据与待实测项见[实现与验证记录](implementation-status.md)。

## 1. 开发原则

按“安装包基础验证 → 单平台人工接待与问答事件 → 本地 Agent 配置与扩展 → AI 回复 → 常驻学习 Agent Loop → 其他平台 → 发布完善”的顺序推进。每个阶段有可运行的结果和验收证据，不能以依赖安装完成代替功能验证。

第一条真实业务链路选择拼多多。其他平台的权限和通道调研可以提前进行，实际实现顺序以验证结果决定。首版覆盖四个平台是产品目标，不是当前支持声明。回复 Agent、Toolkit、Workflow 和子 Agent 必须形成可配置、可试跑、可用于生产回复绑定的完整功能；学习使用内置 Agent，不要求可搭建。单机版不建设组织、成员或团队工作区。

## 3. M0 必须验证的技术组合

### 3.1 运行时与依赖

- 固定开发工具链与 pnpm 版本，提交 lockfile。Prisma 先验证 7.x 的 client、adapter、CLI 组合，不使用 `@latest` 意外升级到不同主版本。
- 记录 Electron、内置 Node.js、Chromium、Prisma、Mastra、LibSQL 驱动及其原生引擎版本。
- 核对 `engines`、ESM 加载、业务进程入口路径和 preload 沙箱兼容性。
- 单独构建 utilityProcess 的入口，确保安装包引用构建产物而非源码路径。
- 验证本地 LibSQL 驱动在目标架构加载，确认 native 模块所需的解包与构建策略。

具体依赖版本在本阶段验证后写入兼容记录。electron-builder 的配置项随主版本可能变化，使用对应版本的文档，不能拼接不同版本的配置示例。参考 [Electron 原生模块](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)与 [electron-builder](https://www.electron.build/)。

### 3.2 本地数据库与迁移

- Prisma 通过 LibSQL adapter 创建、读取、更新记录，验证事务、外键、唯一约束与时间类型。
- 本地文件 URL 在中文、空格和非 ASCII 用户目录下可用。
- 固定版本的 Prisma 迁移执行器能随安装包离线运行，能够从空库和上一版本数据库升级。
- 迁移资源、生成的 Prisma Client 和该版本所需原生资源均已包含，无运行时下载依赖。
- 验证事务失败、迁移失败和磁盘写入失败不会被报告为成功。
- 验证两个数据库文件的一致备份、恢复和索引重建路径。

Prisma 本地迁移执行器是技术验证重点。若这条分发方式不能通过，先记录新的迁移决策并验证，再进入 M1；不得在用户数据库上使用开发重置来规避问题。

### 3.3 Mastra 与本地业务进程

- 在 utilityProcess 中按配置快照构建并执行一次结构化 Agent 调用和一个多步骤 Workflow；用模拟已回答事件验证常驻消费者能够唤醒、保存学习结论，并在空闲时停止模型调用。
- 模型供应商不可达或未配置时，应用可启动并使用人工接待与本地知识管理。
- LibSQLStore 能保存必要运行状态，LibSQLVector 能在本地创建、写入和筛选查询索引。
- 验证受支持的工作流挂起/恢复行为，并明确不具备检查点的执行阶段。
- 关闭和重启业务进程，界面显示状态并重新连接；消息任务依据业务数据库恢复。
- 检查浏览器 bundle、日志和错误响应，确认未包含模型密钥或数据库访问代码。

M0 可先使用模拟平台适配器验证系统行为，避免把平台接入问题与本地运行时问题混在一起。

### 3.4 动态配置与扩展运行

- 按两个不同 Agent 发布快照创建实例，验证提示词、模型、Memory 与挂载成员确实不同，草稿不会自动进入生产。
- 加载一个至少含两个工具的 Toolkit 集合与一个至少含两条原生 Mastra Workflow 的集合，校验声明、工厂返回成员、schema 和 ID 映射。
- 将构建后的 JS 扩展产物从用户数据目录载入真实安装包，验证 ESM、依赖解析、SDK / Mastra 版本及错误提示；不依赖 ts-node 或开发机 node_modules。
- 验证 Workflow 与子 Agent 步骤沿用宿主上下文、预算和取消信号；内置学习不能通过流程取得发送、知识批准或用户编排调用能力。验证调用上下文注入所需的锁定版 Mastra API。
- 保存确切代码 / 配置快照，杀死业务进程后恢复；缺失旧产物时明确停止该运行，不自动改用最新版。

### 3.5 M1a 的交付闭环

交付开发者模式开关、预置默认可删除的回复 Agent 与一键加回、回复 Agent 列表 / 编辑 / 复制、草稿冲突处理、独立调试、发布与历史恢复、子 Agent 挂载。未开开发者模式时定制模块不可见，设置页在默认 Agent 缺失时仍能一键加回。工作设置只能选择全局默认及店铺 **回复** Agent。不提供学习 Agent 选择器。提供集合设置表单、成员 schema / JSON 试跑、运行记录、本地扩展构建安装指引、配置导入导出及缺失依赖报告。

示例至少包括两个可切换的回复 Agent、一个被挂载的子 Agent、一个多工具 Toolkit 集合、一个由 Agent 实际调用的多 Workflow 集合。M1a 使用模拟平台完成配置到调用的闭环，M2 / M3 再验证真实接待与内置学习；普通用户保留可直接选择的内置回复模板。

本阶段不建设组织登录、成员管理、对外 AppKey、可视化流程画布或扩展市场。

## 4. 核心验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 两个店铺同时收消息 | 会话、知识和模型上下文不串店 |
| A02 | 同一消息重复投递、由多个账号接收 | 投递记录可追踪，逻辑消息与回复任务正确去重 |
| A03 | 买家连续发送完全相同的真实消息 | 不因纯文本哈希误删真实输入 |
| A04 | 买家连续追问，旧生成尚未完成 | 使用最新消息组，旧回复不能发送 |
| A05 | AI 生成期间人工点进该会话 | 打开后不提交新的自动发送；在途边界明确；离开后只处理之后的新消息 |
| A06 | 原平台发生人工作答 | 能观测的通道更新本机会话状态；限制明确的通道降级 |
| A07 | 平台已接收但响应丢失 | 进入 unknown / waiting_confirmation，不盲目重发 |
| A08 | 持久化发送意图后杀死业务进程 | 重启先对账，不重新产生同一发送意图 |
| A09 | 旧执行者在租约失效后返回 | 旧令牌不能覆盖新状态或重新取得发送权 |
| A10 | 模型超时、限流、额度耗尽 | 有限重试或降级，界面可见原因，人工接待可用 |
| A11 | 问答候选包含订单号、临时折扣或冲突政策 | 不直接变成通用自动回复依据 |
| A12 | 知识停用后向量尚未删除 | 业务回查过滤旧知识，模型不能继续引用 |
| A13 | 更换 Embedding 模型 | 使用独立索引构建与切换，不混用旧向量 |
| A14 | 应用升级中断或迁移失败 | 停止接待，保留恢复证据，原始数据可恢复 |
| A15 | 恢复比当前平台状态更旧的备份 | 历史发送重新核对，不把旧待办全部重放 |
| A16 | 休眠、断网、重新登录和账号切换 | 重新核验身份与能力，补拉或显示断档 |
| A17 | 恶意买家文本、知识指令或伪造 IPC | 不能扩大工具权限、读取其他店铺或执行本地代码 |
| A18 | 界面重载、重复点击人工发送 | 查询恢复状态，稳定操作 ID 防止重复创建发送 |
| A19 | 店铺关闭自动回复 | 所有会话停止自动生成买家回复和自动发送；人工发送与独立启用的学习仍可用 |
| A20 | AI 转人工后买家继续发消息 | 在人工显式交还 AI 之前不再自动回复；交还后只处理之后的新消息 |
| A21 | 转人工后只打开不发送就离开 | 会话保持等待人工，AI 不得接管 |
| A22 | 意图匹配分数超过高阈值 | 不调用 replyAgent，原样发送最匹配问答对的文字或图片；启用学习后仍做事后评估 |
| A23 | 最高分未超过阈值 | 进入 Agent；可检索问答对、调用已验收平台工具或转人工 |
| A24 | 高分命中但知识已停用或图片缺失 | 不得直答，转入 Agent 或转人工 |
| A25 | 新问题到达但尚未产生实际回答 | 保存待回答回合，不做最终答案评估；空闲不持续调用模型 |
| A26 | 问答对原样直答已确认，实际却匹配错意图 | learningAgent 检查当时分数、意图与答案，记录误匹配并提出限定范围的修正 |
| A27 | AI 回复缺少依据、或与工具结果冲突 | 评估不合理 / 不确定，不把该回答直接变成正确知识 |
| A28 | 自动回复关闭、学习开启，由本机或原平台人工回答 | 不要求人工离开会话即可学习；可复用回答形成待审批建议，人工来源不豁免审批 |
| A29 | AI 回答后人工补充或纠正 | 来源版本递增并重评，生成新待审批建议；旧评估或批准不能覆盖新知识 |
| A30 | 发送 unknown 后获得确认，同时收到回显和历史推送 | 只关联一条实际回答，同一回合版本不重复学习或重复建问答 |
| A31 | 回答入库后、内存通知前杀死业务进程 | 从持久化事件恢复学习任务，无静默丢失 |
| A32 | 学习模型请求进行中关闭自动学习 | 旧代次不再提交新建议；已有建议仍可审批，已批准发布不受开关阻止，接待不被影响 |
| A33 | 审批或发布建议时，人工已修改同一条知识 | 目标版本校验拒绝覆盖，候选标为过期，重新比较并由人工再次审批 |
| A34 | 索引更新、AI 自评或已有问答对多次回显 | 不自触发无限学习，不把派生回显算成新的独立事实佐证 |
| A35 | 一次回答由文字加图片组成，之后又补充 | 有限窗口内合并，后续更新版本；图片不可理解时标记不确定 |
| A36 | 原平台回复无法可靠关联问题或来源未知 | 保留待关联 / 不确定状态，不按最近文本强行创建错误问答 |
| A37 | 真实来源被撤回、删除或知识已到有效期 | 按数据有效性规则过滤并复核；新的学习修订或重新启用仍需要人工批准 |
| A38 | 学习限流、超时或预算耗尽 | 有界重试并显示积压，正常接待继续，不静默跳过三类回答 |
| A39 | 学习判断当前问答有效，但没有新知识 | 保存评估和使用记录，不强制制造新问答或无意义修订 |
| A40 | 高置信度直答、AI 或人工回答产生新增 / 修改建议 | 一律 pending_review，正式知识和生产索引不变，直答及 replyAgent 均无法使用未审批内容 |
| A41 | 人工批准当前候选版本 | 保存人和内容版本，经二次校验后仅发布获批内容，再更新生产索引 |
| A42 | 人工编辑候选内容或替换图片 | 生成新候选版本，必须批准编辑后的内容；不能继承旧版本的批准 |
| A43 | 人工拒绝建议 | 记录原因，不创建正式知识或生产索引任务；原知识保持原规则 |
| A44 | 重复点击批准、重试或发布期间重启 | requestId / applyKey 去重，同一批准只应用一次；无批准记录的任务不能发布 |
| A45 | 待审批期间关闭学习或重启应用 | 建议继续待审批，可人工批准或拒绝；不因超时、关停或恢复而自动批准 |
| A46 | 批准后、发布前，来源或目标知识已变化 | 拒绝沿用旧批准，标记 stale / conflicted，重新形成建议并审批 |
| A47 | 学习 Agent 判断知识错误并提出停用、改范围或阈值建议 | 只展示报告和待审批建议，不自动改变生效知识、排序或匹配阈值 |
| A48 | 编辑或发布当前回复 Agent 的新版本 | 草稿可独立调试；发布后已绑定该 Agent 的接待跟到最新版，未发出的旧回复失效 |
| A49 | 设置全局默认与店铺覆盖的回复 Agent | 店铺覆盖优先，无覆盖才继承；更改全局只影响继承店铺；学习无绑定可选 |
| A50 | 自动回复生成中或 prepared 时切换回复配置 | 旧代次不得发送；仅仍有接待资格的未回答消息可以新配置重排，不复活人工暂停时取消的旧消息 |
| A51 | dispatching / unknown 时切换配置 | 保留原意图与快照并先对账，不用新 Agent 版本创建第二个回复意图 |
| A52 | 学习评估中变更内置版本或 LearningPolicy | 旧执行不能提交新候选，重排未完成工作；已完成评估 / 候选保留旧版本；切换回复 Agent 不影响学习去重键 |
| A53 | 多个店铺与买家共用同一回复 Agent | 配置可复用，生产 / 调试、店铺、会话 Memory 和工具上下文不串用 |
| A54 | 多工具和多 Workflow 集合挂载、逐成员试跑 | 集合配置与调用入参分离，每个声明成员按 schema 可调用且能追踪 |
| A55 | 工厂成员缺失、额外成员、重名、别名冲突或输出不符合 schema | 发布 / 装载或调用校验失败，不能静默注册错误成员 |
| A56 | 回复绑定缺少模型、子 Agent、必填配置、兼容产物或确切历史版本 | 拒绝无效激活；运行时失效显示原因，Agent 路径转人工，不能静默换 Agent；内置学习故障只积压学习任务 |
| A57 | 回复 Agent 只挂载部分平台集合或账号能力变化 | 工具受挂载与实时能力交集约束；searchQaPairs / handoffToHuman 保持可用，身份范围不可改写 |
| A58 | 内置学习 Agent 请求发消息、批准、发布知识或调用用户编排 | 宿主接口拒绝；候选仍待人工审批，生产知识、发送与回复绑定不变 |
| A59 | 挂载 Workflow 返回越界数据、递归调用或试图接管学习 | 宿主契约与预算检查阻止继续，不跳过高阈值、人工交接、内置学习或审批规则 |
| A60 | 调试 Agent、工具或流程并生成回答 / 候选 | 写入隔离测试存储，模型调用计费可见，不发送真实买家消息或污染生产学习队列 |
| A61 | 更新集合设置、轮换密钥或安装扩展新版本 | 非密钥设置生效有版本与代次；明文不入快照；新代码不原地替换旧修订依赖 |
| A62 | 删除被引用 Agent / 扩展、恢复旧备份 | 引用保护和依赖清单有效；无法恢复原代码时明确失败，不替换成最新版或重放发送 |
| A63 | 导入导出 Agent 与扩展配置 | 密钥、Cookie 和客户会话不随默认导出；导入为待检查草稿，不自动安装代码或设为工作 Agent |
| A64 | 同时修改回复 Agent 草稿或工作绑定 | revision 乐观锁拒绝过期写入，不静默覆盖另一份有效配置 |
| A65 | 回复 Agent 挂载子 Agent 并在未过阈值时调用 | 按锁定修订运行，权限不扩大，发送回到本轮 OutboundMessage |
| A66 | 子 Agent 形成环路、指向学习角色或修订缺失 | 发布或运行校验失败，不自动回复，不跳过该子 Agent |
| A67 | 尝试把用户 Agent 绑到学习入口或学习页选择 Agent | 无此接口；学习始终使用内置 Agent |
| A68 | 开发者模式关闭 | 侧栏看不到 Agent Studio、资源目录和工作绑定；自动回复仍按当前绑定运行 |
| A69 | 删除预置默认回复 Agent | 解除其绑定；未过阈值不再走 Agent；重启或关开发者模式不会自动重建 |
| A70 | 一键加回默认 Agent | 按当前模板新建默认资产并绑为全局回复；店铺覆盖不变；已存在未删除的默认 Agent 时不复制第二份 |
| A71 | 未开开发者模式维护问答库 | 可新建、编辑、导入本店问答对；看不到 Agent Studio |
| A72 | 导入含图片的问答压缩包 | 图片落入附件目录，意图-图片可直答；缺图行失败不影响同批成功行 |
| A73 | 编辑已有问答对的意图、文字或图片 | 生成新修订，检索只读生效版；旧答案可审计，不原地覆盖 |

以上是测试环境的验收目标，不是对未验证平台的能力声明。真实发送仅在明确的测试会话执行，普通回归使用模拟与脱敏回放样本。

## 5. 测试分层

| 层次 | 工具与内容 |

## 6. 操作系统与容量验证

首批技术验证目标为 Windows x64 和 macOS arm64；这是建议的验证范围，最终发布支持以安装包验收为准。macOS x64、Windows arm64 和 Linux 后续补充相应构建与实测，不能根据 Electron 的跨平台定位直接宣称支持。

建立容量测试记录，包含机器配置、系统版本、应用与驱动版本、店铺数、常驻页面数、消息数量、问答数量和并发设置。起步样本可使用 2 个店铺账号、10 万条模拟历史消息和 5 千条问答，逐步增加负载。

测量：

- 冷启动与恢复账号耗时。
- 会话列表和历史分页的本地查询耗时。
- 消息到达至入库、自动回复生成、平台确认的分段耗时。
- 主进程、业务进程和各平台网页的内存与 CPU。
- 实时接待和常驻学习并行时的队列等待、积压数量、最老未评估时间和数据库锁等待。
- 问答完成到学习开始、评估结束和候选生成的耗时；人工审批等待与批准后发布 / 索引耗时单独统计。
- 回复、逐轮学习和 Embedding 各自的用量、失败率和估算成本；学习常驻空闲期间的模型调用数。

第一轮实测后形成量化基线和支持范围，再设定发布阈值。模型服务耗时与本地处理耗时分开记录，不对完整回复延迟作无依据的固定承诺。

## 7. 打包与升级流程

构建阶段生成前后端产物、Prisma Client、迁移资源、适配器代码和内置 Toolkit / Workflow 产物与 manifest，包含必要的原生依赖。用户业务数据不进入安装包。

在目标系统完成原生模块加载和真实路径验证，按锁定的 electron-builder 版本配置资源解包；macOS 和 Windows 的签名能力分别验证。稳定的应用标识和签名关系还会影响系统密钥访问与升级体验。

更新包通过配置的发布源下载、校验并由用户在合适时机安装。关闭新任务、保存并核对在途操作、备份、迁移、恢复通道后才重新启用自动接待。签名校验、完整性校验和适配器更新采用同一可信发布流程，不运行来源未验证的远程脚本。

首版平台适配器随应用版本发布。独立热更新要另行设计版本兼容、签名、回滚和最小权限，不能用下载一段脚本立即执行代替发布管理。高级用户的本地 Toolkit / Workflow 使用独立构建、导入启用、发布绑定流程，固定版本与哈希；不得覆盖在途依赖或自动从远程地址执行代码。

## 8. 诊断与运行可见性

本地日志关联 eventId、conversationId、turnId、sourceRevision、evaluationId、candidateVersion、approvalId、reviewerId、applyKey、jobId、aiRunId、intentId、AgentRevision、bindingRevision、configEpoch、RunConfigSnapshot、Workflow 成员、扩展产物哈希和适配器版本。记录处理阶段、错误类型、重试与会话打开原因；默认隐藏正文中的客户资料和所有凭据。

工作台至少显示账号连接状态、独立的自动回复 / 自动学习开关、当前打开的会话、待人工会话、待确认发送、失败任务和知识索引状态。学习视图显示监听 / 评估 / 暂停状态、待评估与待审批数量、每轮匹配与质量判断、建议差异、批准 / 编辑后批准 / 拒绝入口、审批人与发布结果。未审批、已拒绝和已过期结果清楚标记为不生效。配置页显示全局 / 店铺有效 Agent 修订与继承来源、策略 Workflow、资源缺项、设置版本和切换记录；调试与生产记录明确分开。诊断导出由用户触发，包含版本和脱敏事件证据，默认不包含账号 Cookie 与模型密钥。
