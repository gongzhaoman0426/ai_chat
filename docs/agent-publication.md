# Agent 发布与店铺应用

> Workflow 扩展已移除，本文中与 Workflow 相关的内容仅为历史记录，见[本地扩展开发](extension-development.md#workflow-已移除)。

更新日期：2026-09-10。

Agent 在产品中只区分「未发布」「有修改待发布」「已发布」。用户不选择或管理 Agent 版本，编辑器只有一个「发布」按钮。

## 使用流程

1. 创建 Agent，编辑提示词、模型和挂载能力，草稿自动保存。
2. 可以隔离试运行。点击「发布」后，所有已经使用此 Agent 的店铺自动更新，包括全局默认的继承店铺和店铺专用绑定。
3. 新 Agent 首次投入接待时，在「工作绑定」按名称选择。发布不会把其他助手负责的店铺改绑过来，也不会打开自动回复开关。
4. 再次修改仍先保存为草稿，发布后统一生效。相同配置重复发布不新增记录、不递增接待配置代次。
5. 「更多操作 → 发布记录」按时间查看此前的配置，可以恢复为草稿；再次发布后才会影响接待。

已移除「发布并应用」按钮、店铺选择弹窗及对应 IPC 接口。发布与首次选择工作 Agent 分工明确，已有绑定无需重复应用。

## 子 Agent 与工具

子 Agent 按名称选择并设置调用别名，无发布版本选择器。每轮开始时解析它当前已发布的配置；修改草稿不影响接待，子 Agent 发布后，调用它的父助手与店铺自动采用新的配置，无需重新发布父助手。旧挂载的修订 ID 兼容解释为同一个 Agent 的身份引用，不重写历史记录。

Toolkit 自动使用本机已安装且启用的最新版。Workflow 继续使用所选资源产物，Skill 正文、参考资料和脚本仍随所属 Agent 发布时保存的内容使用。

## 内部一致性

- 保留不可变 `AgentRevision`、草稿乐观锁和审计信息，用于恢复和排查，不把编号暴露为用户操作选项。
- `agents.bind` 使用 `agentId`，服务端在事务中选择其当前发布配置。旧内部调用的 `revisionId` 参数继续兼容；不得同时传两种引用。
- 在模型调用前解析完整的子助手与 Toolkit 树，记录到 `RunConfigSnapshot.agentTree`。同一轮按该快照执行，执行记录可还原当时的工具、提示词和模型配置。
- 发布检查最新的完整调用图，禁止直接或间接环路；依赖、设置或授权验证失败时事务回滚。
- 子 Agent 发布同样更新使用它的父级绑定所涉及店铺的 `replyConfigEpoch`。生成中的旧回复失去发送资格，已提交平台的发送继续追踪原回执；不会为更新配置额外请求模型。
- 店铺资源范围、平台能力与子 Agent 的父级权限约束继续校验。自动更新不赋予跨店铺访问权限。
