# 引导与系统设置

更新日期：2026-09-28。适用于拼多多、抖店和闲鱼。

## 配置顺序

以店铺为单位，依次完成「连接店铺 → 全局问答检索 → 配置助手 → 开启接待」。模型服务可以复用，但每家店铺使用哪个助手、哪个模型，以及是否自动回复，都要明确显示。

首次使用、或旧工作空间升级后尚未选择 AI 来源时，先选择「使用自己的 API Key」或「注册账号，使用云端 AI」，也可稍后配置、先使用人工接待。自己的 Key 直接连接用户填写的服务，无需注册；云端账号仅用于充值和按量使用句达提供的 AI。登录云端后，目录中的对话与 Embedding 模型会自动写入本机可用列表，不必再逐个「选用」。选择后进入四步店铺引导。已有店铺或模型不会跳过 AI 来源选择，保留原配置继续使用后也不会反复出现。已有用户可以从侧栏「上手引导」重新配置；日常修改对话模型在「店铺管理」完成，向量模型在引导第二步或系统设置「模型服务」中调整。

| 步骤 | 要配置什么 | 如何完成 | 实际生效条件 |
| --- | --- | --- | --- |
| 连接店铺 | 平台客服账号 | 选择平台，在平台窗口登录并进入客服聊天页 | 自动识别店铺，具备消息接收与文字发送能力 |
| 问答检索 | 全店共用的 Embedding | 选择已同步的云端向量模型，或填写自有向量服务；保存为全局检索模型。可暂时跳过 | 写入 `embeddingProfileId`；切换后后台重建知识索引。不是开启接待的前提 |
| 配置助手 | 该店铺回复使用的对话模型 | 选择已保存的模型，或填写 API Base URL、API Key、模型标识；点击「保存并应用到本店助手」 | 在一次事务中生成助手发布版本、绑定当前店铺并更新配置版本 |
| 开启接待 | 收发确认与自动回复开关 | 先验证实际收发，确认账号，再显式开启自动回复 | 后端重新检查账号、对话模型、资源范围和店铺配置版本 |

模型名称、输出 Token 上限和超时折叠在「更多模型设置」。向量维度须与服务商一致。普通问候和澄清可以直接回答；业务事实与承诺需要当前店铺资料或平台查询支撑。

保存模型和应用助手均不会调用模型。「测试模型连接」由用户显式点击，发起一次简短请求，测试结果以文字展示。它验证当前模型服务可调用，不代表所有平台工具或图片能力已实测。服务参数已修改而助手尚未重新应用时，不把新服务的测试结果显示成旧助手的验证结果。

## 默认助手与本店助手

界面直接展示当前助手名称、配置来源和实际回复模型：

- 使用内置默认助手时，即使已有模型或提示词已经调整过，也可以在引导或设置中「重新配置模型」。保存为当前店铺创建独立的基础助手，其他店铺的全局默认绑定不变。
- 已有本店基础助手时，更换模型更新该助手的发布版本，不重复创建助手，历史发布快照保留。两种入口均仅更新模型，保留提示词、资源挂载、工作流、技能内容快照和子 Agent 挂载。Toolkit 独立按包自动使用最新启用版本，无需通过换模型或重新发布来升级工具。
- 用户新建的自定义助手、有待发布草稿、被多处共用的基础助手，或被绑定到旧发布版本的助手，在 Agent Studio 中调整。简易入口不覆盖待发布修改，高级功能全部免费，仍保留资源适用范围和发布校验。
- 如果模型服务的参数已更新，助手仍使用旧发布快照，界面显示「参数已有更新」并提供重新配置入口。重新选择同一模型并保存，即应用最新参数。
- 仅打开设置或引导不会发布、重新绑定、开启接待或补发消息。

## 日常设置

店铺管理左侧选择店铺，右侧按「平台账号 / 客服助手 / 自动接待」维护。系统设置默认打开模型服务，不再重复设置店铺入口。连接成功不代表自动回复已经开启。未配置的步骤提供对应操作，已配置的步骤允许回访修改。

| 分类 | 用户用途 |
| --- | --- |
| 店铺管理 | 选择店铺，连接账号、配置助手模型、验证收发并开启/暂停 AI 回复 |
| 模型服务 | 添加、编辑和测试可复用的服务配置；保存后可直接跳转到当前店铺应用模型 |
| 高级定制 | 打开开发者工具，管理 Agent、Skill、Toolkit、Workflow 和执行过程 |
| 数据与备份 | 查看本地资料目录、创建和恢复备份、导出诊断 |

「查看当前生效配置与工具」折叠展示完整配置、可用资源和问题定位。基础助手的模型问题直接返回本店模型配置步骤。

自动学习、学习模型与直答阈值放在店铺管理「自动接待」的「自动学习与接待参数」。参数通过明确的保存按钮提交；学习开关独立提交。回复和学习均不设每日调用次数上限，已有店铺的旧限额在升级后移除。学习可使用与回复相同的对话模型，会产生独立用量；生成的新增、修改或停用建议均须人工审批后生效。各店铺独立学习。

全局默认助手模型和向量检索位于模型服务的折叠项。全局默认模型的修改作用于使用该默认助手的店铺，已有本店专用助手不随之换模型。编辑被选作全局默认的模型服务时，沿用现有默认助手自动更新规则；本店基础助手需要重新应用，自定义助手需要重新发布。清晰区分「服务保存」与「助手应用」。

## 收发验证与恢复引导

收发确认需要用户实际检查买家消息能到达聚答、聚答人工回复能到达买家，以及平台原聊天页的人工回答能同步。确认按钮重新检查账号身份与消息通道，不代替用户发送测试消息。图片能力另行实测。

引导进度从当前账号、助手与接待状态计算。用户可以先进入接待中心进行人工回复，之后返回引导；去接待中心测试收发时仍保留「继续配置」。已有工作空间升级后只需确认一次 AI 来源，可保留原配置继续使用；不会要求重新配置店铺或助手。接待引导和系统设置中的「选择 AI 服务」可随时重新打开选择页。

开启 AI 后只处理之后符合资格的新消息；查看会话、人工回复和普通订单操作不暂停 AI。需要暂停时点击「接管会话」；明确转接客服同样进入人工接待。人工接待或 AI 主动转人工后，处理完成需要点击「交还 AI」。重启不会替用户交还会话。

## 实现与验证

- `onboarding.state` 只读提供真实状态、配置来源、实际模型和服务参数是否已更新，不返回密钥。
- `onboarding.configure` 校验当前店铺配置版本和助手是否仍适合简易配置；发布快照、绑定与配置版本在事务中更新。
- `onboarding.enable` 在服务端再次检查接待条件，页面过期时不能覆盖新配置。
- 桌面无新增数据库迁移。AI 来源偏好保存为 `AppSetting.aiSetupMode`，店铺引导偏好继续使用 `AppSetting.setupGuideState`，设置页分类保存在界面状态中。
- 领域回归覆盖默认助手按店铺换模型、其他店铺及自定义配置保留、过期页面、服务更新重新应用、账号和资源检查。
- `node scripts/settings-smoke.mjs` 在隔离的 Electron 工作空间执行引导与设置流程，使用本地模型服务和模拟平台消息。布局截图保存在 `.artifacts`，不会操作真实买家或实际店铺配置。
