# 产品结构与前端交互

更新日期：2026-09-28。

## 产品主线

JuDesk 的日常工作围绕「AI 接待新咨询 → 人工处理例外 → 审批可复用的问答」展开。连接平台、配置模型和编排助手是接待前的准备，不应持续占据聊天区域。

首次使用按「连接店铺 → 配置助手 → 开启接待」引导。日常使用直接进入接待中心。高级用户可以进入工作室编排 Agent、Skill、Toolkit、Workflow，普通用户不需要先理解这些概念。

## 页面职责

| 页面 | 用户在这里做什么 | 店铺范围 |
| --- | --- | --- |
| 接待中心 | 查看各平台聊天记录、回复客户、处理商品与订单咨询 | 独立筛选全部或某一家店铺；打开客户不改变筛选 |
| 问答库 | 新建、编辑、删除、导入、导出文字和图片标准答案 | 明确选择全部、通用或某店专属；查看某店时可同时查看通用问答 |
| 学习审核 | 核对原始问题和实际回答，批准、编辑或拒绝学习建议 | 明确选择一家店铺，审核通过仅写入该店 |
| 店铺管理 | 管理平台账号、客服助手与模型、自动回复与学习 | 左侧选店，右侧分「平台账号 / 客服助手 / 自动接待」维护 |
| 系统设置 | 管理可复用模型、开发者功能、本地数据和备份 | 工作空间级别；应用模型时跳转店铺管理 |
| 高级工作室 | 编排资源、分配工作 Agent、查看逐步执行过程 | 资源自带可用店铺限制；执行页明确选择店铺 |

主导航位置固定，不再设置会同时影响所有页面的顶栏店铺选择器。接待中心的范围与管理页独立，用户不会因查看一个客户而改变正在管理的问答范围。

## 接待中心

### 统一接待界面

- 接待中心只有一个界面，无需选择接待模式。会话列表上方用下拉选择全部店铺或某一家店，中间是聊天记录和回复输入框。店铺状态不占据顶部卡片区域。
- 选中会话即可回复、接管或交还 AI，并查看当前客户的商品、订单和处理记录。业务侧栏由当前会话的实际店铺、账号和买家确定。
- AI 自动接待由店铺开关和会话接管状态控制，日常巡查与人工处理使用同一界面。切换店铺、会话或页面不修改接待策略；人工输入内容按店铺和会话保留在当前进程中。
- 查看会话、查询资料、人工发送文字/图片/富消息和普通订单操作不接管，也不打断 AI 回复。显式「接管会话」或确认「转接客服」才转为人工接待；完成后主动交还 AI。AI 主动转人工仍进入等待人工状态。

### 会话筛选

| 筛选 | 含义 |
| --- | --- |
| 全部 | 当前店铺范围内的会话 |
| 待处理 | 已要求人工处理，但尚未被人工接管 |
| 我接待的 | 本机已明确接管的会话 |
| 未读 | 尚未查看的本地会话 |

打开未读会话后清除未读，接管待处理会话后移入「我接待的」，但当前聊天保持打开，不随筛选结果消失。切换店铺主动清空当前聊天，避免旧店客户与新店操作混用。

会话按最近活动排序，首屏最多 200 条，通过「加载更多会话」继续读取。消息日期分隔显示真实日期；用户上翻历史时，新消息不会强制将视图拖回底部。

### 小窗口

宽窗口并排展示业务侧栏；窗口较窄时从「客户与订单」打开抽屉，关闭后继续聊天。只有侧栏实际展示时才挂载业务查询。更窄时店铺列表改为明确标注的下拉选择，保留聊天宽度。主导航收窄为带文字提示的图标。

## 问答与学习

- 新建问答始终有「所属店铺」。从全部或通用范围新建时默认通用，从某店范围新建时默认该店，保存前可修改。
- 导入先选择「导入到」，再选择文件、预览并确认。导入预览标出目标范围，避免隐含地写入之前管理过的店铺。
- 图片问答在问答表和话术弹窗显示图片预览。话术仍只包含通用和当前会话店铺可用的问答。
- 学习页将待审批队列作为主体。最近评估记录折叠展示；配置学习模型与开关从「学习设置」进入当前店铺的自动接待页。回复和学习均无每日调用次数上限。
- 问答行直接提供「删除」，启用和停用问答均可删除，不再提供归档、恢复或已归档筛选。确认框展示所属范围与文字/图片预览；取消不改变条目，确认后从所有问答列表、话术和知识包导出中移除且不能恢复。历史聊天、引用版本与共用图片保留。
- 学习结果仍必须人工审批，审批绑定内容和来源版本的后台校验保留。界面筛选和布局不改变知识覆盖规则。

## 实现约定

- `inboxStoreId / inboxFilter` 保存接待页状态；管理页使用独立的店铺选择。旧的本机接待模式偏好不再读取。
- `conversations.get` 独立读取当前会话，避免它依赖筛选列表是否仍有这条记录。接口隐藏已移除全部账号的店铺。
- `conversations.list` 支持 `waiting / human` 筛选，以及读取时的 `{ id, updatedAt }` 游标。排序为 `updatedAt desc, id desc`；边界会话之后发生更新，也不会改变已经拿到的分页位置。店铺、搜索与筛选条件始终和游标共同生效。
- 平台业务写操作完成后刷新本地会话详情和列表，防止下一次接管操作使用旧状态。普通消息刷新不重复查询远端平台资料。
- 新增页面和会话读取接口不需要数据库迁移；已有消息、问答、审批记录、Agent 配置与授权数据继续使用。

## 验证入口

- `pnpm build`：类型与生产构建。
- `pnpm test`：领域回归；`tests/reception-navigation.test.ts` 覆盖筛选、独立会话、分页和移除店铺。
- `node scripts/workbench-smoke.mjs`：独立 Electron 工作空间，真实 IPC，模拟三平台 transport；覆盖统一接待、旧模式偏好兼容、草稿、业务操作、问答归属及图片、学习审批、导航与窄窗口。
- `node scripts/settings-smoke.mjs`：首次引导、模型配置、按店应用助手及 Agent Studio。模型测试仅访问测试脚本启动的本地服务。

截图位于 `.artifacts/product-*.png`、`.artifacts/workbench-*.png` 和 `.artifacts/reception-center.png`。真实买家、收费模型和平台业务写入不用于界面验收。
