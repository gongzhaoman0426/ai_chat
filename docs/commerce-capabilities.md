# 客服工作台与店铺客服工具扩展

更新日期：2026-09-11。

本轮基于 botsdk 与 `references/douyin-feige-console.js`，扩展现有的单一「店铺客服工具」Toolkit。平台与账号始终从当前会话解析，不由 Agent 指定。原有 Agent 挂载自动解析最新工具实现，无需重新发布或重新绑定店铺。

## 功能与入口

| 能力 | 拼多多 | 抖店 | 入口 |
| --- | --- | --- | --- |
| 查看会话时同步平台已读 | 支持 | 支持，使用真实消息对象 | 自动执行；不接管会话 |
| 商品关键词搜索 | 原 SDK 未提供 | 支持 | 侧栏「商品 → 店铺商品」及 `goods.keyword` |
| 当前买家订单搜索 | 原 SDK 未提供 | 支持 | 侧栏「订单」及 `buyer-orders.keyword` |
| 发送原生商品卡片 | 原 SDK 未提供 | 支持 | 商品详情、`send-product-card` |
| 视频素材列表与发送 | 支持审核通过素材 | 支持素材中心已有视频 | 侧栏「视频」、`video-materials`、`send-video` |
| 视频消息展示 | 有明确视频地址时可播放 | 有播放地址时可播放，否则展示封面与平台查看提示 | 聊天消息 |
| 查看订单备注与标签/星标 | 支持 | 支持平台返回完整备注和星标的订单 | 订单详情、`order-remark-state` |
| 追加订单备注 | 保留既有流程 | 支持，保留旧备注和星标 | 订单详情、`order-remark` |
| 转客服组、查看客服状态 | 原 SDK 未提供 | 支持 | 侧栏「转接客服组」 |
| 邀请下单 | 原 SDK 未提供 | 支持 | 商品详情 |
| 邀请评价 | 原 SDK 未提供 | 支持 | 订单详情、`invite-review` |

商品来源仍可在关联商品与店铺商品之间切换。新增功能放在已有侧栏，没有新增应用一级导航。抖店视频默认读取「全部视频」，点击平台返回的文件夹进入子目录，点击路径返回上级；无需填写目录编号。

本轮视频发送使用平台已有素材，不包含任意本地视频上传；拼多多参考代码也没有建立本地视频上传契约。抖店素材若只提供 videoId 和封面，不伪造可播放链接。

## 业务服务与发送

- 公共查询 schema、平台能力表、平台桥接、结果归一化、CommerceService、工作台使用同一组操作名。
- Agent 的查询参数与说明按当前平台装配：拼多多、闲鱼、快手的商品列表不暴露 `keyword`；抖店商品列表与订单、快手订单保留关键词搜索。工具工厂提供的当前平台说明随参数一起传给模型，避免模型把通用清单里的跨平台能力当作当前平台能力。历史工具清单及发布快照保持可读取，已有助手运行时自动使用该修正。
- 商品、视频、客服组查询分别返回 `productRef`、`materialRef`、`groupRef`，来源证据绑定店铺、账号、会话、买家、运行或工作台会话；引用有效期 5 分钟。
- 订单读取与修改继续使用 `orderRef`，不能用任意订单号替代当前买家归属核验。
- 商品卡片、视频与评价邀请进入原有 OutboundMessage 队列，界面先显示发送中；只有平台消息编号或可关联消息回执才能确认为已发送。`success: true` 但无消息编号的发送返回 unknown。
- 相同请求幂等；同一会话相同素材仍在发送中或结果未知时复用原发送记录，不因新的点击编号重复提交。
- Agent 查询商品/素材/订单后调用发送工具，confirmed 即结束本轮；不再请求模型生成补充文案。问答关联在执行结果保存后完成，避免自己的消息回执将本轮误判为 STALE。
- 当前消息契约新增 video/product_card/review_card，媒体元数据保存在现有 JSON 中，无需数据库结构迁移。视频内容不可读时不声称模型已经理解视频。

## 备注处理

拼多多复用 `/pizza/order/note/query` 与 `/pizza/order/noteTag/query`。

抖店用当前买家订单查询和目标订单搜索读取现有备注、星标，再调用 `/backstage/workshop/addRemark`。整个过程为：核验订单 → 读取现状 → 生成追加内容 → 再次检查现状 → 宿主授权 → 写入 → 读回核对。

抖店订单响应必须明确提供 remark 与 star；缺失、陌生组件结构或订单不匹配时拒绝写入并说明原因。写入使用 `is_add_star: false`，不会主动改变星标。两平台追加备注都不承诺跨客户端原子性；并发变化、写后无法核对均交人工处理，禁止自动重试。

## 邀请评价与话术入口

Agent 可用 `invite-review`，只接收当前买家订单查询返回的 `orderRef`。发送前宿主再次核验订单归属，再调用飞鸽 `sendCustomCard`（card_type=comment）。评价邀请与其他消息共用发送队列和回执；同一店铺、买家、订单已有发送中、未知或已确认的邀请时复用原记录，避免跨轮次重复催评。

提示词要求只在客户询问评价入口，或确认收货/服务完成且适合邀请时使用；不在问候、投诉未解决或每轮回复时催评。成功后直接结束本轮，无额外模型请求。客服组、客服状态、邀请下单仍仅供人工工作台。

已移除「平台话术」预览、导入入口及对应查询/RPC。聊天输入框旁的「话术」继续使用通用问答和当前店铺问答；已有问答数据和学习审批流程保留。

已移除抖店「结束会话」功能，包括工作台按钮、操作契约、平台能力和桥接调用。旧操作记录保留展示与人工核对能力，不能再次执行。

## 拼多多视频查询响应

2026-09-11 当前登录账号只读查询实际返回 `success:true, error_code:1000000, result:{total:0,file_with_check_dtolist:[]}`。此前沿用聊天协议的错误码判断，将成功当成失败，同时未识别该列表字段。

素材查询现在兼容这一成功封装和列表字段；真正失败、矛盾错误码、未知列表结构仍然报错。聊天协议继续保留原来的零成功码规则。当前店铺没有视频素材时正常显示空列表。

## 抖店视频查询响应

2026-09-11 已对照飞鸽原生素材中心代码，并使用当前登录账号只读核验。`/backstage/search_pigeon_materials` 必须传入 `parent_folder_id`：飞鸽内置的「全部视频」目录是 `203`，「全部图片」是 `103`。这两个编号是平台常量，不是特定店铺的私人目录；店铺身份仍来自当前账号的隔离会话。原实现省略该参数，导致平台返回 `code:-1, msg:"参数错误"`。

查询保留 `material_type:video`、`order_by:UpdateTimeDesc` 和从 1 开始的分页，默认传 `parent_folder_id:203`；切换文件夹后传平台返回的完整字符串编号，不转换为可能丢失精度的数字。

真实响应为 `data:{permission, materials:{total,folder_list,material_list}}`。列表、目录和分页统一从 `materials` 内层解析。视频使用 `material_id`、`video_info.vid`、`video_info.video_cover_url`、宽高及秒数时长。素材中心的 `audit_status:3` 表示审核通过；未通过审核或发送信息不完整时不提供发送入口。权限拒绝或未知响应结构仍然报错，不能显示成空目录。

当前店铺实测返回 1 条审核通过的视频，提供完整发送元数据和封面，但 `origin_url` 为空。界面显示封面和原平台查看提示，不从视频 ID 拼接虚假的播放链接。目录导航与 Agent 的 `video-materials` 复用同一查询适配，发送仍使用当前店铺与买家的 `materialRef`。

## 平台验证边界

本轮自动化验证使用隔离数据库、平台响应样本、VM 注入环境和本地模型模拟服务，没有向真实买家发送消息、修改真实订单或执行转接。拼多多素材空列表、抖店素材非空列表已完成真实账号只读核验；真实视频发送回执和订单备注仍须进一步实机验证。

对于没有建立返回结构的响应，显示具体错误，不视为「空列表」；没有明确发送或操作回执时，保留 unknown 和人工核对入口。退款、小额补偿、改收货地址、任意接口调用不在本轮范围。
