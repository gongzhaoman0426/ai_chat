# 聚答 JuDesk 技术方案

> Workflow 扩展已在开源 Demo 中移除，只保留 Toolkit。下列设计与实施记录中涉及 Workflow 的内容仅为历史说明，兼容方式见[本地扩展开发](extension-development.md#workflow-已移除)。

版本：v0.9

方案日期：2026-09-09

状态：已实现拼多多、抖店、闲鱼、快手与 Windows 千牛接入代码；实际交付、验证证据与待实测项见[实现与验证记录](implementation-status.md)及[千牛接入说明](qianniu-integration.md)。

聚答面向同时经营拼多多、快手、闲鱼和抖店的商家，提供统一客服工作台、AI 自动回复，以及内置学习 Agent 驱动的问答对沉淀。每当新的买家问题获得实际回答，内置学习 Agent 都会检查匹配和回答质量，生成问答新增或修改建议；所有学习结果必须经过人工审批才能生效。

本方案将首版定位为“单台电脑管理多个平台、多个店铺”。业务数据、任务和 AI 编排运行在本机，平台通信与模型调用联网完成。模型推理和 Embedding 请求会传输必要的输入文本；“本地存储”不表示模型调用过程完全离线。

平台预置一个默认自动回复 Agent，普通接待即可使用；该默认 Agent **可以删除**，删除后可 **一键加回**。定制 Agent 模块（Agent Studio、Skills、Toolkit、子 Agent）默认隐藏，只有打开 **开发者模式** 后才可见。自动学习使用产品内置 Agent，不在配置台搭建或替换。单机版不引入 agent-platform 的组织、成员或团队工作区。

全新工作空间先进入全屏四步配置：连接店铺、全局问答检索、配置助手、确认收发并开启接待。模型使用用户填写的 OpenAI 兼容接口。基础助手由引导按店铺创建和绑定；问答、自动学习及高级定制可在开始使用后逐步完善。现有用户和自定义配置保留。

## 已确定的技术决策

| 范围 | 决策 |
| --- | --- |
| 产品名称 | 聚答 JuDesk，项目目录 `judesk` |
| 主语言 | TypeScript，开启 strict |
| 桌面与界面 | Electron + React |
| 构建与包管理 | electron-vite + pnpm workspace |
| UI 组件 | Tailwind CSS + shadcn/ui |
| 界面状态 | Zustand；异步业务查询使用 TanStack Query |
| AI 框架 | Mastra，嵌入本地业务进程；用户编排的 Agent 只服务自动回复；学习使用内置 Agent |
| Agent 配置 | 开发者模式开启后才显示定制模块；预置默认可删除的回复 Agent，可一键加回；子 Agent 仅开发者可见 |
| 高级扩展 | Toolkit / 子 Agent 挂载、TypeScript SDK、本地安装、schema 试跑和 Agent 调用 |
| 用户形态 | 单机单用户、本地资源目录；不引入组织、成员、团队工作区或多租户服务 |
| 自动学习 | 独立店铺开关；内置 LearningLoop / learningAgent，不可搭建；人工审批后入库生效 |
| ORM | Prisma 7.x 兼容基线，负责业务数据；补丁版本在 M0 锁定 |
| 数据库 | 本地 LibSQL 文件，使用 `@prisma/adapter-libsql` 接入业务库 |
| AI 存储与检索 | `@mastra/libsql` 的 LibSQLStore、LibSQLVector |
| 参数校验 | Zod |
| 打包 | electron-builder |
| 验证工具 | Vitest；关键 Electron 界面流程使用 Playwright，兼容性先验证 |
| 架构 | 模块化单体，一个安装包，Electron 主进程、界面进程和独立业务进程 |
| 通信 | 应用内部使用受控 IPC + MessagePort；Windows 千牛外部客户端通过本机回环 HTTP/WS + TCP 桥接 |
| 任务调度 | 业务数据库中的持久化任务，单机消费者，有限并发 |

开发工具链选择 Node.js 24 LTS；安装包实际运行时使用 Electron 自带的 Node.js，必须另外核对兼容性。Prisma 暂以 7.x 为兼容基线；当前官方默认文档已切换到 8，本文的 adapter 与迁移命令按 7.x 文档解释。具体依赖版本在第一阶段验证后锁定，不把文档中的选型视为已验证的版本组合。

## 产品与运行边界

- 自动接待要求应用运行、电脑保持唤醒、网络正常且对应账号登录有效。关闭主窗口可驻留托盘；退出应用会停止本机接待。
- 四个平台分别验证接入渠道，不预先承诺都能零后端接入。遇到必须提供公网回调或服务端保密凭据的渠道，需要单独设计最小服务。
- 首版知识学习采用常驻事件循环：新买家问题 → 问答对 / AI / 人工实际回答 → **内置**学习 Agent 评估 → 待审批的新增 / 修订建议 → 人工批准 → 正式知识与向量更新。逐轮触发，无需等会话结束；待审批不阻塞下一轮学习。学习 Agent 不是用户搭建的编排资产。
- 自动学习开关独立于自动回复和人工接待状态。所有学习建议统一人工审批，包括高置信度或来自人工回答的结果。未审批内容不参与直答、回复 Agent 或生产索引。关闭自动回复仍可学习人工作答；关闭学习后已有建议仍可审批。模型训练或微调不属于首版交付。
- 首版不包含多电脑实时协作；后续可增加局域网主机或服务端，统一接待任务归属。多个店铺可以复用同一回复 Agent 配置，但模型记忆与业务权限按店铺、会话隔离。
- 定制 Agent 模块仅在开发者模式开启后可见；关闭开发者模式不删除已有编排，只隐藏入口。发布已绑定的回复 Agent 后，对应工作入口自动切到最新版；安装新扩展或改绑其他 Agent 仍需在工作绑定中确认。修改草稿不影响接待。
- 平台预置默认自动回复 Agent，可以删除。删除后若没有其他有效回复绑定，未过阈值的问题不再走 Agent，只保留高阈值直答，必要时转人工。重启或关闭开发者模式都不会偷偷重建；需要时由用户 **一键加回** 默认 Agent 并重新绑为全局回复。
- 问答库的新建、编辑、导入、启停 **不需要开发者模式**。支持「意图-回答」和「意图-图片」两类问答对；导入与编辑是人工作业，校验通过后写入本店正式知识并更新索引，不走学习 Agent 审批队列。
- 第一条实测业务链路选拼多多。现有 `botsdk` 仅作为阅读参考，其源码能力不能视为 JuDesk 已实现能力。
- 店铺接待只有两种状态：开启 AI 自动回复，或关闭自动回复。查看会话、人工发送文字/图片/富消息和普通订单操作不暂停 AI；原平台同步到的人工回答也不打断 AI。点击「接管会话」或明确「转接客服」才暂停该会话，必须明确点击「交还 AI」才接待之后的新消息；切换页面、托盘和重启保留接管状态。AI 可通过「转人工」工具交出控制权。自动回复必须满足该平台对应能力的验收条件。

## 设计约定

1. 业务库是原始消息、问答原文、接待状态和发送意图的权威记录；Mastra 记忆与向量索引不替代业务记录。
2. 所有业务操作携带由系统验证的平台、店铺、账号和会话上下文，模型不能自行扩展访问范围。
3. 可重试任务通过唯一标识和状态检查去重；平台发送结果不明时进入待确认状态。
4. 人工接管或交还 AI、转人工、消息变化、路由变化和应用重启都会触发发送前复核。
5. 平台差异留在适配器，AI 逻辑留在 AI 模块，界面通过业务接口发起操作。
6. 学习以问题与实际回答形成的回合为单位。重复事件去重，补充 / 纠正按来源版本重评；学习结果不直接向买家发送消息，也不因自身索引更新循环触发。
7. 内置学习 Agent 只写评估和待审批建议；人工批准绑定具体内容、来源与目标版本。新增、修改、补充问法、替换图片或停用都不能跳过审批，重启也不自动批准。用户编排不得接入学习入口。
8. 用户可编排的 Agent、Toolkit 和子 Agent 只用于自动回复，且只在开发者模式中配置。运行开始时保存有效配置快照，切换回复绑定使尚未发送的旧配置结果重新接受校验。配置不能突破会话隔离，也不能把子 Agent 扩权成学习或审批角色。
9. 一键加回默认 Agent 是显式用户操作：按当前产品模板新建一份默认回复资产并绑为全局回复；不恢复已删除修订的历史 ID，也不改写仍有效的店铺覆盖。
10. 问答库对人可见、可导入、可编辑，含图片答案。人工维护与学习建议分开：前者由用户直接落库，后者仍须审批。
11. 文档内的数据表、目录与 TypeScript 片段是实现契约或建议结构，尚不是项目中已经存在的代码。

新增实现若改变进程边界、数据库归属、发送状态机或平台接入方式，应同步更新对应文档和验收项。
