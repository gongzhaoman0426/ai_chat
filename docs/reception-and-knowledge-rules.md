# 接待控制、问答优先级与生效配置

更新日期：2026-09-28。本文描述当前实现；历史验收记录中的“查看暂停、离开恢复”和“人工发送后自动接管”已由显式接管替代。

## 查看与接待分开

- 打开会话只清除本地未读，不更改接待方、会话修订或在途回复。正在查看时，新消息仍可由 AI 接待。
- 点击「接管会话」暂停本会话的 AI，取消未提交平台的旧回复。人工发送文字、图片、话术或富消息不改变接待模式；原平台同步到的人工回答也不打断当前或后续 AI 回复。人工回答仍按实际发送结果归档并参与学习。
- 切换会话、切换页面、窗口进入托盘、应用重启，都不解除人工接管。可以同时接管多个会话。
- 处理完成后点击「交还 AI」。只允许之后的新消息进入自动接待，不补发接管期间或更早的问题。店铺自动回复关闭或账号不具备接待条件时，交还不会自动打开开关或承诺开始回复。
- 交还请求携带页面看到的会话 revision。期间来了新消息或新的转人工请求会拒绝过期操作，避免覆盖新状态。
- 仍有 prepared / dispatching / unknown 发送时不能交还；需要等待或核实回执。发送成功只确认送达，不代表同意结束人工接待。
- 接待中心的备注、发货等普通业务操作不接管当前会话；明确确认「转接客服」仍会暂停本会话 AI。会话已由人工接待时，业务操作仍在提交、回执未知，或成功转接未核对时不能交还；在处理记录中核对后再主动恢复，原回执状态保留。界面与扩展接口详见[接待中心与业务操作](reception-workbench.md)。
- AI 转人工后显示「等待人工处理」和原因。人工接管后显示「人工接待中」，明确交还后按店铺开关和账号状态显示 AI 接待状态。

数据库保留 `openedByHuman` 字段以兼容既有资料，语义改为“人工接管中”。当前查看会话 ID 仅保存在业务进程内存。`humanSentAfterHandoff` 保留历史审计用途，不再控制自动交还。`conversations.open` 只管理查看，新增 `conversations.reception` 管理显式接管和交还。

## 问答覆盖与冲突

问答仍只在通用库或所属店铺使用，学习结果仍需人工审批。学习修订已有问答时保留原先的明确覆盖关系；审批预览展示商品、条件与覆盖目标，人工编辑可以调整。

1. 向量检索维持原有一次请求，同时检索本店和通用知识。业务服务回查 SQLite，校验归属、生效修订、有效期、学习审批及来源状态。
2. 同一意图的店铺规则优先于通用规则。意图归一化只处理字符宽度、大小写、空白和结尾问号等，不声称自动识别所有语义相同的问题。
3. 问法不同但业务上要覆盖通用规则时，在问答编辑器选择「覆盖通用问答」。`scope.overridesEntryId` 随知识修订保存，只能由店铺条目指向未删除的通用条目。修改所属范围会清除该选择。
4. 根据同意图与明确覆盖关系，从数据库补齐整个规则组，即使本店覆盖或商品规则未进入向量 top-K，也要参与选择。这一步不额外调用模型或 Embedding。
5. 无条件的本店规则替代关联的通用答案；存在商品或条件规则时，交给现有回复 Agent 核对适用性，不直接套用通用答案。Agent 按适用的商品专属、本店、通用顺序使用规则。
6. 最高分须严格超过直答阈值。最高候选附近（分差不超过 0.04）有不同答案，或有关联的商品/条件规则时，暂停直答，走同一次正常 Agent 回复。分差是保守的候选歧义门槛，不是“正确概率”。图片答案按附件 ID 判断是否相同。
7. Agent 自己调用知识搜索时也执行同样的覆盖和有效性检查。适用性无法确认时应查询现有工具或向买家澄清，不能靠相似度混合不同承诺。
8. 编辑器展示相关规则、答案及范围，图片可以预览。不进行额外的模型冲突扫描；问法不同且未显式关联的语义冲突不能保证全部发现。

知识发布、范围或启停变化使相关店铺的旧回复配置失效。正在生成且未提交平台的回复取消，对应客户进入待人工处理，避免因知识变化反复消耗模型请求。已经提交平台的消息继续处理原回执，不重复发送；尚未开始的任务可使用新配置。人工审批学习建议本身不直接改写生产答案，正式发布时才执行上述失效处理。

## 当前店铺的生效配置

「系统设置 → 账号与接待」的每家店铺显示「当前接待配置」，普通用户无需开启开发者模式即可查看：

- 实际工作的 Agent 名称和本店专用/继承全局来源。
- 已发布配置中的实际回复模型；自动学习开关和实际学习模型。
- 未发布草稿、模型配置已变但未重新发布等提示。已绑定该 Agent 的店铺在发布后使用最新版。
- 连接、模型、资源版本和必要设置缺项，附配置入口。
- 展开后显示挂载的 Skill、Toolkit、Workflow、子 Agent，以及当前店铺权限和每个账号的平台能力是否允许调用。部分可用时列出成员与可用账号。子 Agent 继续遵守父级能力限制。

`stores.configuration` 是本地只读查询，不调用模型、不执行扩展代码、不返回密钥/密钥引用/设置值/提示词。该总览是配置和连接状态检查，不替代真实平台接口的收发测试。

Agent Studio 仅提供「发布」，自动更新所有使用此 Agent 的店铺；首次选择助手在工作绑定页完成。发布记录按时间查看和恢复为草稿，内部保留不可变快照。子助手发布同样更新父级接待；未提交平台的旧回复失效，已提交的发送继续追踪回执。详见 [Agent 发布与店铺应用](agent-publication.md)。

## 验证范围

回归测试覆盖查看及人工回复不中断生成、普通业务操作不隐式接管、显式接管/跨重启保留、交还不重放旧问题、发送未知时禁止交还、迟到回执不自动交还、覆盖未进入向量候选、条件规则与重复答案阻止直答、不同店铺隔离、学习批准校验，以及生效配置和发布应用事务回滚。

Electron 验证使用临时数据目录和本地模型/平台夹具，检查真实 IPC、界面操作和窄窗口布局。不会给真实买家发送消息，不执行真实订单修改；Windows 实机与真实账号长时间运行仍需在对应环境单独验收。
