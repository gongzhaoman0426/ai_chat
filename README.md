# 句达 · 开源 Demo

单机运行的 AI 客服工作台。已接入拼多多、抖店、千牛、闲鱼和快手，在统一接待中心查看聊天、回复客户并处理商品和订单咨询，支持 AI 自动回复和需人工审批的问答学习。业务数据库、任务、Agent 配置与附件保存在本机；平台通信、对话模型和 Embedding 按需联网。

这是去掉云端服务和付费功能的纯净 Demo 版本：没有账号、云端 AI、Pro 套餐、充值或自动更新，全部功能直接可用。模型接入只需填写任意 **OpenAI 兼容接口**（OpenAI、DeepSeek、通义千问、智谱、火山方舟、Ollama 等）的 Base URL、API Key 和模型名称，费用由你选择的服务商结算。

项目按 `docs` 的 v0.8 设计实现。当前提供可运行源码和 macOS Apple Silicon 应用包；真实拼多多账号的端到端收发仍需联调，不能将离线夹具通过视为平台验收完成。实际交付范围与测试证据见 [实现与验证记录](docs/implementation-status.md)。

日常入口分为「接待中心 / 问答库 / 学习审核」；账号、助手和自动接待配置集中在「店铺管理」，模型与本地数据在「系统设置」。[产品结构与前端交互](docs/product-experience.md)说明完整页面职责和接待流程。

## 启动

开发环境使用 Node.js 24、pnpm 11。首次在项目目录执行：

```bash
pnpm install --frozen-lockfile
pnpm db:generate
pnpm dev
```

桌面主进程自动准备数据库并执行 Prisma migrations，不需要单独启动后端、Redis 或数据库服务。`pnpm dev` 使用真实的本地资料库；如需独立测试资料库：

```bash
JUDESK_DATA_DIR=/tmp/judesk-local-demo pnpm dev
```

全新资料库只创建默认回复 Agent 和内置资源，不放入虚构店铺、消息或问答。开发者模式、店铺自动回复和自动学习默认关闭。

macOS arm64 构建产物为 `dist/mac-arm64/JuDesk.app`。该包未签名、未公证，不能视为正式公开发行版。也可自行构建：

```bash
pnpm pack                # 当前系统的应用目录
pnpm dist                # 当前系统的安装包；macOS 为 DMG / ZIP
```

## 第一次使用

首次打开时先填写模型接口：Base URL、API Key 和模型标识。填写地址后可点「获取模型列表」从服务商的 `/models` 读取可选模型，也可以直接手填；不想现在配置可选择「稍后配置」。之后可在「系统设置 → 模型服务」随时添加或修改模型。然后进入店铺配置引导：

1. **连接店铺**：点击「登录拼多多」，在平台窗口登录客服账号并进入聊天页，等待显示「已连接」。
2. **问答检索**：设置全店共用的 Embedding，填写 OpenAI 兼容的向量服务（需要 `/embeddings` 接口与向量维度）。可暂时跳过。
3. **配置助手**：填写对话模型并应用到本店基础助手。「测试模型连接」可选。
4. **开始接待**：用测试会话核对收发，确认账号后点击「开启自动接待」，然后进入工作台。

配置中断后可继续，也能先选择人工接待；侧栏「上手引导」可随时重开。已有用户升级不强制重走，已有定制助手与其他店铺的绑定保持原样。完整操作与模型修正方式见[首次配置与日常设置](docs/onboarding.md)。

开始使用后可逐步补充文字 / 图片问答、开启自动学习或进入高级定制。自动学习单独开启，所有学习建议仍需人工审批；首次引导创建的助手在之后开启学习时可提供模型默认值，不必再寻找额外模型入口。向量模型也可稍后在上手引导或系统设置「模型服务」中修改。

人工文本点击发送后，气泡立即显示“发送中”并清空输入框；后台收到平台确认后更新为“已发送”，失败或回执未知会显示对应状态，不自动重发。同一会话的文本按顺序发送，切换页面不会中断。

打开会话会暂停该会话的 AI；人工文本尚在发送时不会被 AI 抢答。AI 转人工后，需要打开会话、人工消息确认发送、离开会话才交回 AI；先离开后收到确认也能完成原来的接待。原平台观测到的人工作答同样可以触发学习。

人工回复确认后自动携带发送时的买家消息与会话上下文参与学习，无需手动配对；只有其他来源的未关联回答保留人工关联入口。模型生成草稿、发送中、发送失败及结果不确定的消息都不会直接当作已回答回合。

关闭主窗口会驻留托盘，退出应用停止接待。电脑睡眠或断网期间不工作；唤醒后尝试恢复已连接账号，登录过期需回到平台窗口处理。已明确断开的账号不会自动连接。重启不重放旧自动回复；不确定发送需要核对回执。

普通工作空间只保留客服工作台、问答库和自动学习。模型逐步调用位于开发者工具下的「Agent 执行」；关闭开发者工具会隐藏入口，历史记录仍保存在本机。日常发送状态和连接提示在对应业务页面查看，支持排查时可从「系统设置 → 数据与备份」导出诊断。

## 问答导入

文字问答可以导入 JSON 数组，或 `{ "items": [...] }`：

```json
[
  {
    "intent": "现货多久发货？",
    "answerKind": "text",
    "answer": "现货商品付款后 48 小时内发出。",
    "scope": { "productIds": [], "conditions": "" }
  }
]
```

图片问答使用 ZIP，根目录为 `manifest.json`，图片使用包内路径：

```text
questions.zip
├── manifest.json
└── images
    └── colors.png
```

```json
[
  {
    "intent": "有哪些颜色可以选择？",
    "answerKind": "image",
    "answer": "",
    "image": "images/colors.png"
  }
]
```

导入会先预览，每行独立校验；缺图和错误行不影响成功行。同意图冲突默认跳过，可编辑现有条目。图片上限为 8 MB，接受 PNG、JPEG、WebP、GIF。人工保存或导入的有效问答立即生效；学习候选必须审批后生效。

仅当相似度**严格高于**阈值且知识有效、没有尚待判断的商品 / 业务条件时，发送问答原文或原图。其余情况进入当前回复 Agent。停用或修订的旧知识即使仍有向量记录，也会被业务回查过滤。

## Agent 与高级扩展

在系统设置打开开发者模式，导航中显示「助手」「Skills」「扩展」（Toolkit / Workflow）和「Agent 执行」。全局默认助手在「助手」页选择，单个店铺可在店铺管理的「当前接待配置」中单独指定。

- 回复 Agent 支持提示词、模型、Memory、工具集、流程集和锁定修订的子 Agent。
- 草稿自动保存并可隔离试运行，点击发布后才影响接待。店铺专用助手优先于全局默认。
- 默认回复 Agent 可删除；删除后重启不会重建。设置页可一键恢复，已有店铺覆盖保持不变。
- 学习 Agent 始终为产品内置，不能作为用户 Agent 创建、挂载或替换。
- Skill 支持 `SKILL.md + references/ + scripts/` 编辑、ZIP 导入导出、按需加载、脚本试运行与不可变发布副本；Agent 可通过 `runSkillScript` 执行挂载版本的脚本。在助手编辑器中选择已有技能或新建并挂载，详见 [Skills 技能库](docs/skills.md)。
- Toolkit 和 Workflow 是挂载给 Agent 的能力集合，由 Agent 按需调用；每个成员都有独立输入 / 输出 schema。店铺只选择使用哪个助手，没有额外的回复策略入口。
- Toolkit 挂载一次，自动跟随本机最新启用版本；旧助手也适用，无需重新发布。每轮记录实际工具版本，详见 [Toolkit 自动使用最新版](docs/toolkit-latest.md)。
- 调试使用独立 `sandbox` 存储、平台和知识夹具，不向真实买家发送。调试模型请求仍会产生供应商费用。

可直接复制修改两个 TypeScript 示例：

- [店铺话术 Toolkit](toolkits/local/shop-helpers/index.ts)
- [回复整理 Workflow](workflows/local/reply-polish/index.ts)

```bash
pnpm extensions:build
```

生成 `extensions-dist/*.zip`，在资源目录安装、填写集合设置，然后挂载到 Agent 并发布。扩展格式、上下文接口和试跑方式见 [本地扩展开发](docs/extension-development.md)。本地扩展在业务进程执行，应只安装自己信任的代码；它不是针对恶意代码的安全沙箱。

## 数据与备份

实际业务目录可在系统设置查看，通常位于 Electron `userData` 下的 `judesk-data`。可用 `JUDESK_DATA_DIR` 完整隔离业务数据与浏览器资料。

```text
judesk-data/
├── db/judesk.db          # Prisma 业务数据、任务、审批、配置
├── db/mastra.db          # Mastra Memory 与向量
├── attachments/          # 已校验图片
├── extensions/           # 版本 / 哈希锁定的扩展代码
├── secrets/              # Electron safeStorage 加密的模型密钥
├── sandbox/              # 调试存储与调用用量
└── backups/              # 恢复前的保留副本
```

系统设置提供备份与恢复。备份包含一致性数据库快照、附件、扩展和完整性清单，不包含浏览器 Cookie、系统密钥或调试存储。恢复会重启应用、关闭自动回复、取消旧自动发送，并保留恢复前目录。迁移到另一台机器后需重新登录平台和填写模型密钥。

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm extensions:build
pnpm test:e2e
pnpm pack
JUDESK_PACKAGED=1 pnpm test:e2e   # 本机 macOS arm64 应用包验证
pnpm format:check
```

`test:e2e` 使用临时资料库、测试店铺和本地模型夹具，覆盖实际 Electron 主进程 / utilityProcess / IPC / UI，不访问真实店铺或付费模型；截图写到 `.artifacts/`。退出测试后删除临时资料库。

代码结构：

```text
apps/desktop/src/         # Electron main / preload / service / React
packages/contracts/      # Zod IPC 与领域契约
packages/database/       # Prisma schema、迁移和 LibSQL 连接
packages/core/           # 接待、任务、发送、学习、审批和备份
packages/agent-config/   # Agent 草稿、发布快照和绑定
packages/ai/             # Mastra、Memory、向量与扩展装配
packages/platforms/      # 平台适配与消息规范化
packages/extension-sdk/  # Toolkit / Workflow 接口
resources/*-bridge.js    # 各平台固定页面桥接
```

目前四个平台均有首版适配代码。快手本轮新增账号识别、实时消息与回执、历史消息、买家订单、客服查询和客服组转接，并按当前账号能力向统一「店铺客服工具」开放。平台权限、页面版本和双向收发仍需使用真实账号验收；更多设计见 [技术文档入口](docs/README.md)。

## AI 自动回复已开启却没有回复

先查看接待台右侧的实际接待状态。平台登录、消息通道连接、账号验收分别记录；只有消息通道就绪且已完成验收的账号可自动接待。账号未就绪时开关不能直接开启；历史保存为开启的开关会显示“AI 自动回复已暂停”和具体原因，也可以随时关闭。

1. 到“系统设置 → 拼多多账号”，确认“消息通道已连接”。
2. 在自己的测试会话核对接收买家消息、本机人工发送的确切回执以及原平台人工回复观测，再点击“验收确认”。若发送结果仍待确认，先在会话中核对发送状态，必要时开启开发者工具到「诊断与日志」排查，不能直接假定发送成功。
3. 回接待台打开“AI 自动回复”，离开正在查看的会话，再用一条新买家消息测试。此前的问题不会自动补发。
4. 若显示“等待人工”，查看会话上方的转人工原因；需完成人工回复并离开会话后才交回 AI。模型等运行错误可在开发者工具的「诊断与日志」中查看。

收到消息但未通过账号前置条件时不会调用模型。自动学习仍由独立开关控制，学习建议仍须人工审批。

普通文字回复直接采用 Agent 正常结束时的最后一步正文，由本地代码补齐回复类型、上下文依赖等结构字段；不强制模型将客服正文改写成 JSON。图片或显式动作可以通过同一轮 `submitReply` 工具提交，转人工继续使用 `handoffToHuman`。两种方式均不额外请求模型整理或修复格式，需要查询知识或其他工具时保留正常 Agent 循环。工具错误、无效参数、空正文、截断输出均不会直接发送；推理内容和工具执行前的说明也不作为最终回复。学习仍使用单次结构化结果生成，学习建议须人工审批。

Agent 正常决定转人工时，运行记录与任务都记为成功，保留转人工原因，并发送一次“已为您转人工，请稍候。”。该提示不增加模型请求，也不算人工回复或学习样本。目前是转交本机工作台等待人工，不代表已分配到某位指定的拼多多客服。提示的发送状态在发送记录单独显示，结果待确认时不会自动重发。

若模型错误已导致会话转人工，修复配置后也需要完成该会话的人工处理，再接待后续新问题。

## 自动学习失败

先在「系统设置 → 高级定制」打开开发者工具，再到「诊断与日志」查看学习任务的结束原因和用量。学习仍只调用一次模型，由本地代码解析完整 JSON 并校验；成功结果只进入待人工审批，不会自动发布问答。

- 显示输出达到上限：模型未完成完整结果；在模型设置调整最大输出 Token 后，可以手动重试这条学习任务。
- 显示空结果、JSON 或字段错误：本次不会生成候选，也不会自动重复调用模型；核对模型兼容性后再手动重试。
- GLM-5.3 / GLM-5.3-Flash 的学习采用 `low` 思考强度，保留配置的输出 token 上限。旧版本的 `received undefined` 记录缺少用量，无法据此判断当时是截断还是格式错误；历史记录不补造诊断数据。

### AI 生成成功但平台没有回复

在 **开发者工具 → 诊断与日志 → AI 运行** 查看两项独立状态：“AI 已生成”是生成结果，“发送成功 / 发送待确认 / 发送被拒绝”是关联发送的实际结果。展开详情可看到 `outbounds` 中的发送 ID、平台消息 ID 和原因；只有 `confirmed` 表示收到精确成功回执。

“发送待确认”时，在 **发送异常** 查看具体原因并核对平台记录。未知结果不自动重发，也不作为已经回答的学习来源。平台明确拒绝会保留错误说明；旧版本未记录的拒绝详情无法从历史数据补回。

Agent 编辑器只需点击「发布」，所有使用该 Agent 的店铺自动更新；店铺助手与子助手均按名称选择。详见 [Agent 发布规则](docs/agent-publication.md)。

接待中心支持客户、商品、订单、备注、可用平台的客服转接及闲鱼无需物流发货；具体能力与扩展方式见[接待中心与业务操作](docs/reception-workbench.md)。界面专项验证：构建后运行 `node scripts/workbench-smoke.mjs`，使用独立资料库及模拟平台。
